Ответы на вопросы для самоконтроля

1. Какие три основные области работы с файлами в Git и чем они отличаются?

- Рабочая папка (Working Directory)** — текущие файлы на диске, которые вы редактируете.
- Индекс (Staging Area)** — промежуточная область, куда попадают файлы после `git add`; именно это попадёт в следующий коммит.
- Репозиторий (Repository)** — история зафиксированных коммитов (папка `.git`).

Отличие: рабочая папка — «черновик», индекс — «подготовка к фиксации», репозиторий — «архив версий».

2. Что происходит при выполнении команд:

- `git add` — копирует текущее состояние файла в индекс (staging area), подготавливая его к коммиту.
- `git commit` — сохраняет содержимое индекса в историю репозитория с уникальным хешем и сообщением.
- `git push` — отправляет локальные коммиты в удалённый репозиторий (например, на GitHub).

3. Почему важно писать информативные сообщения к коммитам?

Чтобы по истории было понятно, *что* и *зачем* изменилось. Это ускоряет поиск багов, откат, ревью и работу в команде. Сообщения вида «update» или «fix» бесполезны.

4. Чем отличается `git add имя_файла` от `git add .`?

- `git add имя_файла` — добавляет в индекс только указанный файл.
- `git add .` — добавляет все изменённые и новые файлы в текущей директории (рекурсивно).

Первый вариант лучше для точечных коммитов, второй — когда нужно зафиксировать сразу много изменений.

5. Что показывает `git status` и как меняется её вывод?

Показывает текущее состояние: какие файлы изменены, какие в индексе, какие не отслеживаются. Вывод меняется на каждом этапе — после `add` файлы переходят из «Untracked/Modified» в «Changes to be committed», после `commit` список очищается.

6. Для чего нужна `git remote add origin URL` и что означает «origin»?

Команда привязывает локальный репозиторий к удалённому по указанному URL. `origin` — это стандартное **имя-псевдоним** удалённого репозитория (можно назвать иначе, но `origin` — соглашение).

7. Зачем нужен флаг `-u` в `git push -u origin main`?

`-u` (или `--set-upstream`) связывает локальную ветку `main` с удалённой `origin/main`. После этого достаточно писать просто `git push` / `git pull` без указания ветки.

8. Что такое ветка по умолчанию и почему это важно?

Это основная ветка, в которую попадают коммиты по умолчанию. Раньше Git использовал `master`, сейчас GitHub — `main`. Важно, потому что от неё создаются другие ветки и на неё настроены CI/CD, деплой и т.п.

9. Как просмотреть историю коммитов и какую информацию она даёт?

`git log` — показывает хеш, автора, дату и сообщение каждого коммита. `git log --oneline` — компактный вид. `git log --graph --all` — визуализация ветвления.
